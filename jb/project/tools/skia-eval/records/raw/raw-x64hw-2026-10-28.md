# Raw records, x64hw, 2026-10-28

**JBR's own Vulkan pipeline on Windows: built, two Windows bugs fixed test first, then RenderPerfTest n = 5: 2.68x the software loops (geomean), against Direct3D 9's 1.74x and Skia's 0.78x**

- Build: the Skia release brings the Vulkan headers (`include/third_party/vulkan`, `VK_HEADER_VERSION 347`);
  the shader compiler is Khronos' glslang 16.6.0 (`build/downloads/glslang-16.6.0-windows-x86_64-release.zip`,
  sha256 `82bf434e…8d9b`, unpacked under `build/tools/glslang-16.6.0`, `glslang.exe` copied to
  `glslangValidator.exe`, the name configure looks for). `build/scripts/build.sh`: `WITH_VULKAN=1` adds
  `--with-vulkan-include=<skia>/include/third_party/vulkan --with-vulkan-shader-compiler=glslangValidator`,
  and the glslang directory is on PATH for configure and make (the configured compiler is a bare
  name). `conf-skia` reconfigured: `VULKAN_ENABLED:=true`. The loader is the NVIDIA driver's
  `System32\vulkan-1.dll`. On Windows the pipeline needs `-Dsun.java2d.vulkan=Force` ("experimental").
  It lists the RTX 3080 Ti (default) and the CPU's integrated Radeon.
- `smoke/PipelineProbe.java` (new): the configuration, the surface of a VolatileImage and of a window,
  and a pixel of each (getSnapshot, Robot; the window always on top, else Robot reads whatever covers
  it while the user works). Vulkan: `Win32VKGraphicsConfig`, `VKOffScreenSurfaceData`,
  `Win32VKWindowSurfaceData`, both pixels right.
- Bug 1, `Win32GraphicsDevice.getConfigurations()`: its single-accelerated-configuration branch
  covered OpenGL and Skia, not Vulkan; the GDI pixel-format enumeration after it replaced the default
  with a GDI configuration. A program that lists the configurations first (RenderPerfTest does) got
  GDI and the software loops (`sun.java2d.trace=count`: `MaskFill(AnyColor, Src, IntArgb)` and
  `GDIBlitLoops::Blit`), so the first trial matched software. `VulkanDefaultConfigTest` (red in both
  orders, green after; commits `3bf5d815b99`, `a83da90e3c6`).
- Bug 2, `WToolkit.sync()`: it synced GDI, OpenGL, Direct3D and Skia but not Vulkan (WLToolkit does).
  RenderPerfTest's volatile mode syncs inside each timed frame (`paintTest(…, doSync = true)`), and
  the render queue holds 6.4 MB (`RenderQueue.BUFFER_SIZE`), so on Vulkan the frames ran after the
  clock: 10-20x everything else in the second trial. `VulkanToolkitSyncTest` (3740 bytes queued, still
  queued after the sync before the fix, none after; commits `ba81678d65e`, `f40943779f6`). The Skia,
  Direct3D and software numbers of earlier records were synced and stand.
- RenderMatrix on Vulkan (`build/skia-eval-out/matrix-vulkan`): 821 of 1152 cells within 32 levels of
  the software loops, 342 identical (Skia 865 / 321; Direct3D 9 342 within 32 on 2026-10-22).
- RenderPerfTest, `-e=volatile`, all 65 tests, arms software, d3d, skia-analytic, vulkan, n = 5
  interleaved (`build/skia-eval-out/rpt-vk/summary.txt`; d3d without the XOR tests, as before).
  Geometric mean of the per-test ratio to software: **vulkan 2.68x** (65 tests), **d3d 1.74x** (59),

**Text benches with JBR's Vulkan pipeline, n = 5 interleaved: Vulkan is 3x the software loops on LCD lines, 4.3x Skia, 12x Direct3D 9; flat under glyph churn**

- `bench/run-text-benches.sh build/conf-skia/images/jdk build/skia-eval-out/text-vk 5` with
  `EXTRA_ARMS=vulkan` (new: extra arms in LcdTextBench, GlyphChurnBench and StartupCost); 300 values,
  0 NA. Both benches end a frame with a one-pixel readback from the VolatileImage into a
  BufferedImage, which waits for the frame's commands on the GPU, so the Vulkan times include
  completion (unlike RenderPerfTest's volatile mode before the sync fix). The skia arm is the
  default now (twopass). ms, median:

  | bench | software | d3d | skia (twopass) | vulkan |
  |---|---|---|---|---|
  | LcdText 100 lines | 1.58 | 6.26 | 2.22 | **0.66** |
  | LcdText 500 lines | 6.75 | 25.65 | 9.29 | **2.23** |
  | LcdText 1000 lines | 13.23 | 51.09 | 18.16 | **4.23** [4.22-4.27] |
  | LcdText 90-line grid | 1.41 | 5.86 | 2.00 | **0.62** |
  | GlyphChurn 200 / 600 gray | 0.42 / 0.44 | - | 0.44 / 0.48 | **0.21 / 0.22** |
  | GlyphChurn 1500 / 3000 gray | 0.79 / 1.81 | - | 1.16 / 3.02 | **0.28 / 0.40** |
  | GlyphChurn 1500 / 3000 LCD | 1.10 / 2.85 | - | 1.80 / 6.05 | **0.28 / 0.41** |
  | StartupCost frame 1 (Skia cache off) | 226.0 | 237.6 | 615.3 | 227.9 |
  | StartupCost first window paint | 5.1 | 5.2 | 3.2 | 4.6 |

  Vulkan's glyph handling barely grows with the number of distinct glyphs (0.21 → 0.41 ms from 200
  to 3000 LCD glyphs); Skia's grows 12x. Vulkan starts up like the loops (no shader compilation at
  first use: its shaders are compiled at build time, the glslang step); Skia's first frame still
  pays 390 ms of pipeline compilation without the cache.
