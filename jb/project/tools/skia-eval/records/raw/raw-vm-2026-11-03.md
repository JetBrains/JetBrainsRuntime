## Windows text decorations as Direct2D places them (user: "implement OS-consistent underlines and decorations with the same strategy we've been using for the macOS version")

**What the platform does, measured.** Two Windows conventions exist, and they differ:

- **GDI** (the `gdi` sheet arm, `TextOut` with `fUnderline`): whole device rows, top row = baseline row + round(p),
  rows = max(1, round(t)), p and t the post table's underline position and thickness scaled to the size (probe
  `build/text-reference/probes/underline_rows.py` over the 2026-11-02 sheets; `postmetrics.py` for the tables: Inter
  upem 2816 pos −464 t 192, JetBrains Mono 1000 / −155 / 50, Segoe UI 2048 / −178 / 119, Consolas 2048 / −266 / 144).
- **Direct2D's text renderer** (`DrawTextLayout`, pixel snapping on — what every DirectWrite application gets, the
  same rectangle the sheet tool's `directwrite` arm draws; new probe `dwref --decorations <fonts> <dpi> [nosnap]`, the
  layout drawn with its baseline on device row 40, mean darkness per row over the text's extent, at 96 / 120 / 144 /
  192 dpi for Inter 13, JetBrains Mono 13, Segoe UI 13, Consolas 12):
  - **Underline:** the top row is baseline + round(p) in all 16 cases; the **thickness stays fractional and is
    antialiased downward** (Inter 13 @ 96: row 2 darkness 223 ≈ 0.886 · 255; @ 192: row 4 = 255, row 5 = 191 ≈ t 1.773 − 1;
    JetBrains Mono 13 @ 96: one row at 161 ≈ 0.65 — no minimum thickness). `NO_SNAP` moves only the top to its
    fractional position.
  - **Strikethrough:** an **unsnapped rectangle** from baseline − `strikethroughPosition` (the OS/2 table's top of the
    stroke) down by the thickness; D2D's coverage steps are eighths. All 16 cases fit within one step: e.g. Inter 13 @ 192
    (position 8.513, t 1.773 → band 6.74..8.513 above the baseline): rows 6 / 7 / 8 above = 64 / 255 / 128 (predicted
    66 / 255 / 131); Segoe UI 13 @ 96 (3.364, 0.647): rows 2 / 3 = 64 / 96 (72 / 93 → eighths 64 / 96); Consolas 12 @ 192
    (6.0, 1.195): rows 5 / 4 = 255 / 64 (255 / 50). A first fit was off by half for the proportional faces: the probe
    had measured the period run (the strikethrough text) over the width of the full-text underline pass — fixed.
  - **No gaps** where the ink crosses an underline (DirectWrite draws through the descenders), as recorded before.

  The system convention for the Skia backend is **Direct2D's** (the same text stack as the platform mask route and the
  JDK's DirectWrite path); GDI's whole rows are noted, not implemented.

**The metrics' meaning differs between Skia's hosts.** `SkFontMetrics` documents `fStrikeoutPosition` as the distance to
the *bottom* of the stroke, and the Mac's rule (`strikethroughCentre = position − thickness / 2`) was fitted to CoreText on
that reading; Skia's DirectWrite host (`SkScalerContext_win_dw.cpp`, `generateFontMetrics`) sets it to
`−(dwfm.strikethroughPosition · size / upem)`, DirectWrite's value being the OS/2 table's top of the stroke — so on Windows
the Skia value is the **top**, and the Segoe UI strike metrics the Skia scaler reports (underline 1.130 / 0.755,
strikethrough −3.364 / 0.647 at 13 px) are exactly dwref's DirectWrite numbers. The Windows rule reads them as the top;
`Font2D.getFontMetrics` publishes the strikethrough centre by the platform's reading (`TextDecorations.strikethroughCentre`).

**Implementation (same strategy as macOS: one rule, same arithmetic in Java and native, the platform decides).**
`SKTextDefaults` gains `decorationRule` (`SKDecorationRule::CoreText | DirectWrite`; Windows DirectWrite, macOS CoreText —
a **blind edit in `MTLSKPlatform.mm`**, one initializer line), mirrored by `SKEnvironment.decorationRule()`
(`TextDecorations.Rule`, by `os.name` as `decorationsSkipInk()` is). `TextDecorations.underlineBand` returns {top,
height} as doubles: under DirectWrite's rule {round(p), t}, under CoreText's the whole rows as before; `fillBand` fills a
band of fractional height (Java: an antialiased `Rectangle2D.Double` under the identity transform; native: `drawRect`
with AA); `drawStrikethrough` under DirectWrite's rule fills [baselineRow + centre − t/2, + t) unsnapped; `underlineBottom`
for the bounds is the ceiling of the band's bottom (the bounds reach the partially covered row). The paragraph route
(`SKBackend.cpp`, `drawSystemDecorations`) does the same from `SKPlatform_TextDefaults().decorationRule`. macOS arithmetic
unchanged (CoreText's rows, gaps, clearance).
