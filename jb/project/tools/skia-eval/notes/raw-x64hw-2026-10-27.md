**Dawn's D3D12 backend (`sun.java2d.skia.dawnBackend=d3d12`, experiment, commit `1fe6b812203`): functional and pixel-identical, but 3 % slower to paint in the IDE; submit gets cheaper, insert and present dearer**

- Context: Chrome ships WebGPU on Dawn's D3D12 backend on Windows since Chrome 113; Skia tests
  Graphite on Windows "primarily with Dawn's D3D11 backend although D3D12 should be functional"
  (skia-discuss). The property reorders the backends Dawn is asked for (read in the Windows
  `initNative` before the first adapter request); default unchanged. `SkiaDawnBackendTest`: the
  default and `=d3d11` give D3D11, `=d3d12` gives D3D12.
- Function: the Skia jtreg set with `JTREG_EXTRA_OPTS=-Dsun.java2d.skia.dawnBackend=d3d12`: 47 run
  lines pass; failures: `SkiaDawnBackendTest`'s default line (expects D3D11, the forced option made
  it D3D12, which shows the option reached every run) and the known `SkiaFontScalerMetricsTest`.
  RenderMatrix (1152 cells) on D3D11 and D3D12: **the two sheets are byte-identical** (`build/skia-eval-out/matrix-d3d12`);
  both 865 cells within 32 levels of the software loops, 321 identical.
