## Items (review §3, R10–R15), in order

1. **R10 — Dawn returns error objects, not null.** `device.CreateTexture` and `surface.Configure` never yield `nullptr`; an oversized texture or a second flip chain on an HWND today produces a surface that cannot present and a WARNING per flush instead of the GDI fallback. Wrap creation and `Configure` in `PushErrorScope(Validation)` / `PopErrorScope` + `WaitAny` (or `ProcessEvents` + callback) and return `nullptr` on error; check `limits.maxTextureDimension2D` before creating. Verify with a 20k-px window surface request (DrawHugeImageTest-style) → GDI fallback, no WARNING loop.
2. **R13 — device loss only logs.** Set a `lost` flag on the config in the device-lost callback; `SKPlatform_BackendTexture`/`SKPlatform_RequestRedraw` return false/skip on a lost device; surface it to Java (`Win32SKGraphicsConfig`/`Win32SKSurfaceData.setSurfaceLost` like D3D's `setSurfaceLost` → restore / GDI fallback). Re-`Configure` on `SurfaceGetCurrentTextureStatus::Outdated`. Verify by forcing a reset (`dxcap -forcetdr` in a dev VM, or a display-settings change).
3. **R11 — old swap chain lifetime.** (a) `Win32SKGraphicsConfig.createSurfaceData(peer, …)` passes `previous = null`: dead with the manager installed — make it return GDI unconditionally and fix its Javadoc. (b) `bbNum != 0` (BufferStrategy back buffers) and (c) the GDI fallback leave the old chain configured until GC + Disposer because `FLUSH_SURFACE` releases only the Skia wrapper; release the Dawn side synchronously when a window surface stops being the peer's (a `releasePlatformSurface` on the Java side under the queue lock, or `SKPlatform_DisposeSurface` from `FLUSH_SURFACE` for window surfaces). Verify GDI visibility under a live flip chain (currently unknown).
4. **R12 — off-screen `CreateTexture` off the queue lock.** `Win32SKSurfaceData.OffScreen` creates its texture on the caller's thread while the flusher uses the same `wgpu::Device`. Either request `FeatureName::ImplicitDeviceSynchronization` at device creation (Dawn supports it) or create under `SKRenderQueue.lock()` like the window path.
5. **R14 — `DawnSKSurface::config` raw pointer.** Hold `wgpu::Device` and `wgpu::Queue` by value in the surface; a stale config pointer after a display change (Disposer ran the config first) is a use-after-free. Also verify the cross-device case: a `wgpu::Surface` moved between surfaces whose configs own different devices (`Configure` with another device) — if it fails, re-create the surface instead.
6. **R15 — `-Dsun.java2d.d3d=true -Dsun.java2d.skia=true` ends in silent GDI** (`ScreenUpdateManager` picks D3D). Clear `d3dEnabled` in `WindowsFlags.initFlags` when Skia is requested, as the OpenGL/Vulkan flags do, and log it under `verbose`.
7. **R2 (shared code, Windows-visible)** — a source surface from another config is wrapped with the destination's recorder; valid when both configs share one device (macOS), not when each `Win32SKGraphicsConfig` owns a `wgpu::Device`. Test: a window with a cached `TexturePaint`/`VolatileImage` dragged across two monitors with different adapters (or two configs forced). If Dawn's uncaptured-error callback fires, make `SKBackend` read back and re-upload when `src->state->cc != g.cc`.

## Round 5 (added 2026-10-19, evening) — after the Mac verification of round 4

Your two commits are on both lines (`main` and jbr25). Both build on macOS, the matrices and the window scene are unchanged, and the LCD probe reproduces your fidelity numbers for single strings. One defect, fixed on the Mac in `SKQuadBatch.h` and folded into the two-pass commit:

- **Two-pass batches must split on overlap.** Both passes run over the whole mesh, so two overlapping quads of one batch produce `dst·(1−c₁)(1−c₂) + s·c₁ + s·c₂` instead of the sequential result; the overlap is `s·c₁·c₂` too bright. The Mac `LcdBackgrounds` draws a second copy of the first string shifted by one pixel (two glyph lists of one colour in one batch): before the fix 600–700 px per cell were more than 32 levels off (gray-187 on white turned white at the overlap, max 121); after `splitOnOverlap = !p.asBlendMode().has_value() || passes != nullptr` the overlap column matches the plain column (max ≤ 23). Single strings improved too (glyph boxes within one string overlap by the padding).
- **Please measure the cost of the split on Dawn**: `LcdTextBench … lcd cheap` for 100 / 500 / 1000 lines in the default `twopass` (now with the split) against your round-4 numbers (2.7 / 8.9 / 14.2 ms) and the software loops (1.4 / 5.8 / 11.7). The split costs a draw pair per overlapping group and no destination copy, but with the padding overlap of adjacent glyphs that is about one pair per glyph.
- **If it is too slow**, the next step is a split on *ink* overlap: per atlas cell, record the tight bounds of the pixels above a small coverage threshold (e.g. 8/255) at upload (`SKGlyphCache` `upload`), keep them with the cell, and test those bounds instead of the quad bounds in `push()` (the uncached path keeps the quad bounds). The residual error is then bounded by the product of the filter tails below the threshold. Measure `LcdBackgrounds` with the overlapping column and `LcdTextBench` again; the default stays `twopass` on Windows only if both are acceptable, otherwise this becomes a user decision (§14 D9).
- Also open from your round 4: the two `pow` per channel per pass in the LCD shader (LUT or cheaper fit), and a `DisplayChangeProbe` run on the final branch after the rewrite.

Add an overlapping second string to your `LcdBackgrounds` if it does not have one; the Mac version lives in `build/skia-smoke/LcdBackgrounds.java` on the Mac (private, not in the repository).

**Rule from here on (user, 2026-10-19 night): every finding comes with a jtreg test that is red before the fix and green after.** Two exist now in `test/jdk/jb/java/awt/Graphics2D/TextRender/`: `SKLcdTextBackgroundsTest` (per `sun.java2d.skia.lcd` mode, with an overlapping second list) and `SKGlyphCacheEvictionTest` (a frame with more glyphs than cells, against the software loops).
