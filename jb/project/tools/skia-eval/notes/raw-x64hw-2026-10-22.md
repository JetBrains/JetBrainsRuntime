# Raw records: Windows x64 hardware machine (x64hw), 2026-10-22

Summary: first session on real Windows x64 hardware (Ryzen 5 5600G, RTX 3080 Ti, Dawn on D3D11).
Build: the shared tip `309b521cf1e` does not compile on Windows (missing includes from `03bd323e5c2`,
fixed by a `fixup!`). Correctness: 26 of 27 jtreg Skia run lines pass (the failure is
`SkiaFontScalerMetricsTest`: Windows has no Skia font host yet but `SKFontScaler.isAvailable()` says
it has); the rendering matrix has 865 of 1152 cells within 32 levels of the loops, no new class; a
real TDR is survived with about one black second and Skia stays accelerated (Direct3D 9 falls back to
GDI for good), with one candidate defect in the swap-chain hand-over. Performance (n = 5,
interleaved, off-screen): Skia is 0.57x the loops and 0.67x Direct3D 9 on the geometric mean of
RenderPerfTest, 5 to 9x ahead on AA curves, but 6 FPS on per-frame image uploads and 2.5 to 16x
behind on many small non-AA primitives and plain text; LCD text in accumulate mode is the fastest arm
(1.3x the loops, 5x Direct3D 9); the first frame costs 410 ms of pipeline compilation. On-screen
numbers are vsync buckets (the compositor), apart from LCD text into a window: 10 FPS on Skia and 8
on Direct3D 9. Note for every Windows record: JBR's default pipeline is not Direct3D but GDI
(`sun.java2d.d3d` defaults to false since JBR-7051).
